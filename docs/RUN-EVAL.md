> `ONBOARDING.md` 讲的是**怎么读懂**这个项目。这份讲的是**怎么把它真跑一遍**，
> 拿到能写进简历、能在面试里被追问的数字。
>
> 跑完你手里会有：36 条用例的执行轨迹、三个维度的过程指标、一份 v1 与 v2 的并排对比。
>
> **第一次大约 40 分钟**（其中 20 分钟在申请 Key），**之后每次重跑 10 分钟左右**。
> **按本文的路线走，一分钱不花。**

## 第 0 步 · 先知道自己在干什么

整个流程是四个环节，像流水线：

```
评测集(36 条)
    │
    ├─ 客服 Agent 逐条应答 ──► 每条的完整轨迹（想了什么、调了什么工具、说了什么）
    │        用你的 Key 调模型                    ↓
    │                                    过程指标（轮数/工具成功率/该查没查）
    │                                          ↓
    └─ 评测 Agent 读轨迹打分 ──► 一致率 / Kappa / 漏检误伤
              也调模型                    ↓
                                    和 v1 基线并排对比
```

两个环节都要调模型，所以**没有 Key 是跑不了的**。这是唯一绕不过去的门槛，第 3 步专门解决它。

## 第 3 步 · 申请一个免费 Key

**推荐用智谱，因为 GLM-4-Flash 目前是免费的**，这个项目跑一遍大概几十万 token，用免费的完全够。

### 3.1 注册

1. 浏览器打开 **https://open.bigmodel.cn**（智谱 AI 开放平台）
2. 右上角注册，用手机号收验证码
3. 按页面提示完成实名认证 —— **这步跳过就调不通**，国内平台都一样

### 3.2 拿 Key

1. 登录后进「控制台」
2. 左侧菜单找 **API Keys**（也可能叫「API 密钥管理」）
3. 点「创建 / 新建」，名字随便填，比如 `ai-cs-evaluator`
4. 创建后会显示一串 Key，**复制下来**

> **这串东西只显示一次**。关掉页面就看不到了，只能重新建。建议先粘到记事本里。

### 3.3 一个安全提醒

Key 等于你账户的钱包。**不要发到聊天窗口、不要写进代码、不要提交到 Git**。

这个项目已经做对了一半：`.env` 在 `.gitignore` 里，不会被提交。剩下的一半靠你——别手滑粘到别处。

如果哪天发现漏了，去控制台把那个 Key 删掉，重新建一个就行，不影响别的。

### 3.4 为什么不用 DeepSeek

DeepSeek 也能跑，但**需要先充值**才能调用。按这个项目的用量（36 条用例跑一遍 + 评测 Agent 再跑一遍），大概花几毛钱，不贵，但要绑卡充值。

智谱是 0 元，所以先用它把流程走通。

代价是：**GLM-4-Flash 比 DeepSeek 弱**，跑出来的 Agent 指标会差一些。这个差别在第 8 步会讲怎么处理。

## 第 4 步 · 写 `.env`（Windows 上最容易出错的一步）

### 4.1 复制模板

在项目根目录，把 `.env.example` 复制一份，改名成 `.env`（前面有个点，没有后缀）。

命令行做最稳，不会被 Windows 坑：

```bash
cp .env.example .env
```

### 4.2 填内容

用记事本或 VS Code 打开 `.env`，把这三行改成：

```
LLM_API_KEY=你刚才复制的那串key
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_MODEL=glm-4-flash
```

其余的行不用管，`EMBED_API_KEY` 空着也行（检索会自动降级成纯 BM25，不影响主流程）。

### 4.3 三个必须避开的坑

**坑 1：文件名变成了 `.env.txt`**

Windows 资源管理器默认**隐藏已知文件扩展名**。你以为改成了 `.env`，实际是 `.env.txt`，程序读不到。

怎么验证：

```bash
ls -la | grep env
# 正确的：-rw-r--r-- ... .env
# 错误的：-rw-r--r-- ... .env.txt
```

中招了就在命令行 `mv .env.txt .env` 改回来。

**坑 2：Key 后面带了空格或换行**

复制的时候很容易多带一个空格或回车。程序把空格也当成 Key 的一部分，于是认证失败。

填完之后，光标放到行尾，确认没有多余空白。

**坑 3：给 Key 加了引号**

```
LLM_API_KEY="sk-xxx"     ← 错，引号会被当成 Key 的一部分
LLM_API_KEY=sk-xxx       ← 对
```

`.env` 文件不是 JSON，纯文本就行。

**坑 4：只换了 Key，没换地址（用智谱的话必踩）**

代码里的默认值是 DeepSeek —— `LLM_BASE_URL` 默认 `https://api.deepseek.com/v1`，`LLM_MODEL` 默认 `deepseek-chat`。

所以如果你填了智谱的 Key 却忘了改这两行，程序会**拿着智谱的 Key 去请求 DeepSeek 的服务器**，结果是一个莫名其妙的 `HTTP 401`。你会以为是 Key 错了，其实是地址没换。

三行是一套，要么全改，要么全不改。

### 4.4 确认读到了

填完跑这条，验证配置有没有被正确加载：

```bash
.venv/Scripts/python.exe -c "from src.config import LLM_API_KEY, LLM_MODEL, LLM_BASE_URL; print('Key 长度:', len(LLM_API_KEY)); print('模型:', LLM_MODEL); print('地址:', LLM_BASE_URL)"
```

Key 长度应该是 30 以上的一串数字。如果打印 `Key 长度: 0`，说明文件没被读到（回去看坑 1）；如果长度是个位数，八成是带了空格。

## 第 5 步 · 先跑 3 条（不要一上来跑满）

```bash
.venv/Scripts/python.exe -m src.eval.runner --limit 3
```

这一步的目的**不是看分数**，是验证三件事：Key 通不通、模型认不认 `function calling`、网络会不会超时。

### 正常的话，屏幕会这样滚

先是头部：

```
==============================================================
[M7] 客服 Agent · 测试执行器
==============================================================

模型：glm-4-flash
判例库：21 条（仅收答对样本）
待跑：3 条（--limit 模式）

开始执行 ...
```

然后是每条一行：

```
  [ 1/3] #1    2 轮   3521ms  answered   search_precedents → get_order_detail
```

最后是过程指标。

### 那一行怎么读

```
  [ 1/3] #1    2 轮   3521ms  answered   search_precedents → get_order_detail
   └┬─┘  └┬┘   └┬┘    └──┬─┘  └───┬──┘   └──────────────┬───────────────┘
    序号  用例  轮数    耗时    结束原因            按顺序调了哪些工具
```

**结束原因**这一列只有五种值，看到不对劲就查这里：

| 值 | 含义 | 正常吗 |
|---|---|---|
| `answered` | 模型自己说完就收尾了 | 正常，最常见 |
| `human` | 转人工了 | 正常，有些问题本来就该转 |
| `max_rounds` | 转到 6 轮上限被强制掐断 | 有问题，说明它在原地打转 |
| `empty_response` | 模型返回了空内容 | 有问题，通常是模型能力不足或 prompt 太长 |
| `llm_error` | 调用直接报错了 | 看报错信息，多半是 Key 或额度 |

### 报错了怎么办

先看第 12 步的报错对照表。最常见的三个：

- `[X] 没有读到 LLM_API_KEY` → `.env` 文件名或位置不对，回第 4 步
- `HTTP 401` → Key 错了或已失效
- `HTTP 404 model not found` → `LLM_MODEL` 拼错了，或者这模型你这个账号没权限

**3 条全过再往下走。** 3 条都跑不通，跑 36 条只会浪费时间和额度。

> 上面这段数字是**格式示意**，不是你的运行结果。结构来自 `runner.py` 的打印语句，
> 具体数值取决于你用的模型和当时的输出。你的数字大概率不一样，这是正常的。

### 这几个指标里，重点看三个

| 指标 | 为什么重要 |
|---|---|
| `skipped_retrieval` | **最值得警惕的一类**。意思是「这题该查判例，它没查，凭常识答的」。这种答案即使碰巧对了，换个问法就崩。只有过程指标能抓到它 |
| `guard_blocked` | 安全闸门拦了几次。比如用户没确认就要退款，被代码挡住了。这个数大于 0 说明闸门真的在工作 |
| `工具成功率` | 低于 95% 要查原因。工具报错了 Agent 还在编「已经帮您办好」，是最危险的行为 |

`平均轮数` 高不一定坏（复杂问题本来就该多轮），但**持续贴着 6 轮上限**说明 prompt 或工具设计有问题。

## 第 7 步 · 让评测 Agent 读轨迹打分

```bash
.venv/Scripts/python.exe -m src.eval.judge
```

这一步读上一步写出的 `traces.json`，逐条看**完整轨迹**（不是只看最后那句回复），打分并做过程诊断。

**要等多久**：36 条，每条一次模型调用，**3 到 6 分钟**。

### 跑完会看到

```
--------------------------------------------------------------
v2 · 我们的 Agent
  一致率            83.3%
  Cohen's Kappa     0.6412
  判偏率            16.7%
  漏检              无
  误伤              [12]

  过程问题分布（这才是 v1 抓不到的东西）
    fabricated_success     2
    ignored_tool_error     3
    skipped_retrieval      4
    premature_refund       1
--------------------------------------------------------------

--------------------------------------------------------------
对比 v1 基线（支付宝「我的客服」的实测应答）
                    v1 基线       v2 Agent
  一致率              96.7%         83.3%
  Cohen Kappa         0.9231        0.6412
--------------------------------------------------------------
```

> 同样，**这是格式示意**，数字要看你实际跑出来的。

`过程问题分布` 每一行的含义：

| 标签 | 中文 | 具体是什么行为 |
|---|---|---|
| `fabricated_success` | 编造成功 | 工具明明失败了，回复里说「已经帮您办好了」 |
| `ignored_tool_error` | 无视报错 | 工具返回错误，它当没看见继续往下走 |
| `skipped_retrieval` | 跳过检索 | 规则型问题该查判例，它没查 |
| `premature_refund` | 擅自退款 | 用户没确认，它就把退款发出去了 |

**这四个才是 v2 存在的理由。** v1 完全抓不到它们——v1 只看最终回复对不对，
而上面这四种行为，前两种在结果指标上甚至显示为「答对」。

## 第 8 步 · 怎么读这些数字（重要）

### 先说最容易误会的一件事

**v2 的一致率大概率比 v1 低，而且低不少。**

这不是代码写坏了。原因有三层：

1. **评的对象变了**。v1 评的是支付宝客服的**应答摘要**，一段话，信息量有限，判起来简单。v2 评的是自己造的 Agent 的**完整执行过程**，变量多得多。
2. **标准没变，难度上去了**。评测量表一行没改（这是故意的，为了可比）。同一把尺子量更难的东西，分数自然往下走。
3. **模型能力不一样**。GLM-4-Flash 是免费模型，让弱模型跑 Agent，指标会比 DeepSeek 差一截。

所以看到 70%、60% 别慌。**关键不是「有多高」，而是「哪一类失败在变多」**——那才是过程指标的价值。

### 那么简历上怎么写

**诚实写，并且写清楚条件。**

不好的写法：

> Agent 评测一致率 95%

面试官一问「你们 Agent 用的什么模型、评测集多大、判偏率多少」，立刻穿。

能站住的写法：

> 自建 36 条客服评测集，用规则 + 大模型混合评分对 Agent 做结果与过程双维度评测；
> 过程指标抓出 v1 结果指标看不见的 3 类失败（编造成功 / 无视工具报错 / 跳过检索）。

**注意这段话一个百分数都没有。** 因为一次免费模型的跑分不足以支撑一个漂亮的数字，
但「能抓出三类隐藏失败」这件事本身就是结论，而且经得起追问。

### 如果你想要一个能写上去的数字

两条路：

**路 A（0 元）**：用 GLM-4-Flash 跑，把结果如实记录，写「在 glm-4-flash 上的一致率为 X」。
诚实、可复现，但数字可能不好看。

**路 B（几毛钱）**：充 10 块钱用 DeepSeek 跑一版。Agent 能力更强，指标会好一截。
写「在 deepseek-chat 上的一致率为 X」。有成本，但数字更接近真实水平。

**我的建议**：先用路 A 把流程走通、把代码 bug 都修掉，确认整条链路没问题。
等要投简历前一周，再走路 B 跑一版「正式数据」。别拿第一次跑失败的数字去投。

## 第 10 步 · 跑 v1 的完整链路（可选，约 15 分钟）

v2 是建在 v1 上的。如果面试要你讲「Kappa 是怎么算出来的」，你得真跑过一次 v1 的全链路。

按顺序跑，**每一步都依赖上一步的输出**：

```bash
.venv/Scripts/python.exe -m src.loader      # 读 Excel，清洗成 records.json
.venv/Scripts/python.exe -m src.rules       # 规则引擎打分（不调模型，秒出）
.venv/Scripts/python.exe -m src.llm_judge   # 大模型评审（30 条，1-3 分钟）
.venv/Scripts/python.exe -m src.analyze     # 加权求和 + 算 Kappa
.venv/Scripts/python.exe -m src.report      # 导出 Excel 报告
```

只看不跑行不行？**行，但少一样东西**：`llm_judge` 那一步会真调 30 次模型，
你会亲眼看到「同一段话，模型判 3 分还是 4 分会有波动」——这是理解 Kappa 为什么必要的最快方式。

跑完最后一步，`output/` 里会多一个 `AI客服质量评测报告.xlsx`，打开能看到逐条评分。

**`src.llm_judge` 这一步建议先小批量试**，因为它要真调 30 次模型：

```bash
.venv/Scripts/python.exe -m src.llm_judge --limit 3
```

**注意：它没有断点续跑。** 跑到第 20 条断了，重跑就是从第 1 条重新开始，前面那 19 次额度白花。所以务必先 `--limit 3` 确认 Key 和网络没问题。

有个细节设计得不错：`--limit` 模式的结果写到 `llm_results_partial.json`，而 `src.analyze` 读的是 `llm_results.json`。
**两个文件分开，试跑的结果不会污染正式结果。** 所以你 `--limit 3` 跑完直接跑 `--analyze`，它读的还是原来那份完整数据，不会被 3 条覆盖掉。

## 第 12 步 · 报错对照表

| 你看到的 | 真实原因 | 怎么修 |
|---|---|---|
| `ModuleNotFoundError: No module named 'src'` | 不在项目根目录 | `cd` 到有 `README.md` 的那一层 |
| `[X] 没有读到 LLM_API_KEY` | `.env` 没被读到 | 检查文件名是不是 `.env.txt`、位置是不是项目根目录 |
| `HTTP 401 Unauthorized` | Key 错 / 失效 / 多了空格 | 重新复制一次 Key，注意行尾不要留空白 |
| `HTTP 404 model not found` | 模型名拼错，或账号没这个模型权限 | 智谱用 `glm-4-flash`，DeepSeek 用 `deepseek-chat` |
| `HTTP 429` | 触发限流 | 代码有退避重试，会自动等。连续 429 就隔几分钟再跑 |
| `HTTP 400 response_format` | 模型不支持强制 JSON 输出 | 把 `constants` 里的 `force_json` 关掉，或换模型 |
| 中文输出全是乱码 | 终端编码是 GBK | 换 PowerShell；或先执行 `chcp 65001` |
| `streamlit: command not found` | 没用 venv 的 python | 用 `.venv/Scripts/python.exe -m streamlit run app.py` |
| 改了 prompt 但结果没变 | 有缓存 | 关掉终端重开，最稳 |
| 跑一半断了 | 网络抖动 / 额度用完 | 看 `llm_error` 那几条的报错原文，额度用完就去控制台看余额 |
